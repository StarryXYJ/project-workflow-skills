# 同步项目文档

单独用于用户要求的项目文档维护，也可用于 feature、quick、hotfix 或重构的相关收尾。遵循用户要求及项目文档结构、导航和发布约定。

1. 确定变更范围，检查仓库指令、工作树、已有文档、相关代码、测试、运行结果和 feature 记录；区分已实现并验证的事实、计划、推断和历史。代码与文档不一致时核实证据，无法确认的差异如实报告。
2. 找到现有权威页面并优先更新它；当前契约和架构约束归规范，操作步骤归手册，一次改动的需求、设计取舍和过程归 feature 记录，agent 的踩坑归项目知识体系。遵循现有命名与组织，不强制建立这些目录。
3. 仅将有证据的当前行为写成事实，说明必要的版本、平台和适用条件；不把计划、单次测试或推测写成普遍支持承诺。按需更新索引、交叉链接、示例和相关变更总结，避免复制形成多个事实来源。
4. 运行项目现有的相关文档、链接或示例检查；记录执行结果和未验证项。报告更新位置、依据与剩余差异；没有需要更改的内容时直接说明。

文档同步不自行修改业务行为、提交、推送或发布；用户已明确授权的动作和调用工作流中已有的提交规则除外。不要用生成内容覆盖人工修改或删除未确认的内容。
