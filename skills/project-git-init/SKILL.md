# 项目 Git 初始化

为目标项目建立可维护的 Git 基础配置。先遵守用户与仓库现有指令；已有配置优先保留和增量修订，不为追求统一覆盖项目文件或改变已跟踪文件。

1. **盘点**：确认项目根目录、是否已在 Git 工作树内、Git 状态及现有 `.gitignore`、`.gitattributes`、`.editorconfig`、构建入口和技术栈。识别已有暂存及用户改动。子目录可能属于父仓库，不要误建嵌套仓库。仅在用户要求初始化且确认目标尚无仓库时执行 `git init`；已有仓库不重新初始化或更改分支。
2. **配置**：按需阅读 [默认配置参考](references/defaults.md)，先采用已有约定；新项目推荐 UTF-8、清晰的换行策略和最小通用忽略规则，再依真实技术栈补充生成物。先检查潜在冲突、已有内容及团队要求；只创建缺失配置或有针对性修改，不忽略源码、锁文件、样例配置或必要资产。
3. **验证**：检查变更 diff、`git status`，对代表性的生成物和应保留的文件使用 `git check-ignore -v` 检查；对于重要例外，结合状态和文件是否已跟踪判断。需要检查换行时使用 `git ls-files --eol`。报告本次采用的编码、换行和忽略范围，以及未验证项。

不要自动清理文件、取消追踪文件、统一重写既有文本、执行 `git add --renormalize`、配置远程、提交或推送；除非用户明确要求，或所调用工作流已授权相应提交。不要读取或输出密钥内容；`.gitignore` 不会使已经跟踪的敏感文件安全，也不能代替凭据管理。
