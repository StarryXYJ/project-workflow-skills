# 项目经验总结

用于单独总结已有工作，也可在开发中及时捕获非显然问题，并在收尾时整理。先确定目标项目的知识记录约定和用户要求；复用现有位置，不为普通一次性错误强制新建知识体系。

1. 检查相关任务记录、变更、测试和运行证据以及已有经验，识别重复、过时或与当前实现冲突的内容。当前代码及验证过的正式文档优先于旧记录；不能证实的归因标明是假设。
2. 筛选未来任务可能重遇、风险高或代价高的非显然经验。每条聚焦一个问题，记录适用范围、现象、证据、原因或假设、有效做法及来源；必要时记录不适用条件。用户纠正也是线索，但不夸大其适用范围。
3. 有项目约定时写入现有经验位置并更新简短索引；用户要求持久化且没有约定时，选用适合项目的轻量位置。没有值得沉淀的内容时说明，不制造经验。可用候选、已确认和过时等状态区分证据成熟度；保留历史并标注替代关系。
4. 汇报总结、证据和不确定性；验证相关链接和引用。避免记录秘密、完整对话、个人评价或一次性细节，不将 agent 笔记原样塞入开发者手册。

将经验升级为长期规则或独立 skill 时，先确认其适用边界和现有规则；创建或安装独立 skill 需要用户明确要求，不自动扩大范围。不要因此修改业务代码或发布内容。
