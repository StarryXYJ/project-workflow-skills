# hotfix 工作流

适用于目标明确、范围较小的缺陷修复，按项目已有规则处理；简单修复不强制创建 feature 文档。

1. **分析**：确认问题现象、预期行为和影响范围，检查相关代码与已有改动；尽可能复现或找到证据，区分已确认的原因和假设。
2. **修改**：按授权进行聚焦修复，优先处理原因，避免混入无关改动。若问题范围或风险超出简单修复，转入适当的深入调查或 feature 流程。
3. **验收**：验证原问题及相关回归，记录实际执行的检查、结果和未验证范围；说明修复结果与剩余问题。无法验证时如实说明，不宣称已解决。

全部完成并验收后按 [阶段计划与 Git](phase-and-git.md) 提交一次；如需阶段计划，也遵循其中的详细规划和完成后简化规则。
